# 🧭 MASTER ROADMAP (From 8.2 → 9.5 System)

We’ll break this into **4 phases**:

1. **Stability & Safety (Foundation)**
2. **Control & Integrity (Trust Layer)**
3. **Intelligence & Insights (Decision Layer)**
4. **Scalability & Productization (Future-Proofing)**

---

# 🧱 PHASE 1 — Stability & Safety (Week 1–2)

> Goal: Make your system **safe to use with real data**

### 🔴 1. Remove Dangerous Deletes (TOP PRIORITY)

Replace:

* delete donation/expense/tithe

With:

* `void_transaction`
* `is_deleted` (soft delete)

Add fields:

* `void_reason`
* `voided_at`
* `voided_by`

👉 This alone upgrades your system from “risky” → “accountable”

---

### 🔴 2. Strengthen Audit Logs

Upgrade logs to include:

* create ✔
* update (before/after values)
* void/delete
* login/logout

Structure:

```
user_id
action_type
module
old_value
new_value
timestamp
```

---

### 🔴 3. Input Validation Layer

Enforce:

* no negative amounts
* required fields
* proper date ranges

👉 Do BOTH:

* frontend validation
* backend validation (non-negotiable)

---

### 🔴 4. Error Handling System

Right now errors are probably raw.

Upgrade:

* user-friendly messages
* centralized error handler

---

# 🔐 PHASE 2 — Control & Integrity (Week 3–4)

> Goal: Make the system **trusted by leadership**

---

### 🟡 1. Approval Workflow (CRITICAL)

Add status:

* `pending`
* `approved`
* `rejected`

Flow:

* Staff creates → Treasurer/Admin approves

Applies to:

* donations
* expenses
* tithes

---

### 🟡 2. Permission-Based Access (Upgrade from Roles)

Instead of:

> role = TREASURER

Create:

```
permissions:
- create_expense
- approve_expense
- export_reports
```

👉 This gives flexibility for future scaling

---

### 🟡 3. Monthly Financial Lock

After month ends:

* data becomes **read-only**

👉 Prevents:

* retroactive tampering

---

### 🟡 4. Budget Protection System

Improve your allocation logic:

Add:

* monthly budget snapshot
* warning if exceeded
* prevent overspending (optional strict mode)

---
